# موقع تتبع الطلبات (مراحل التصنيع)

موقع صغير منفصل عن متجرك على **EasyOrders**، وبيترفع **ببلاش**:

- **صفحة العميل** (`/`): العميل بيكتب رقم الطلب ويشوف طلبه في أنهي مرحلة (تم الاستلام ← جاري التجهيز ← جاري التصنيع ← فحص الجودة ← تم الانتهاء ← جاري الشحن ← تم التوصيل)، بأيقونات متحركة.
- **لينك مباشر لكل طلب** (`/track/10234`): تبعته للعميل على واتساب ويفتح على طلبه علطول.
- **لوحة التحكم** (`/admin`): بتدخلها بإيميل وباسورد. فيها بتضيف الطلبات وتغيّر المرحلة، وتبعت للعميل لينك التتبع على واتساب بضغطة.
- **الداتا كلها على Supabase**: لو عدّلت حاجة من Supabase نفسه، صفحة العميل بتتحدّث لوحدها خلال 20 ثانية، ولوحة التحكم خلال 30 ثانية.

> من باب الخصوصية، العميل مش بيشوف اسم ولا رقم موبايل. اللي بيظهر له بس: رقم الطلب، والمنتج، والمرحلة، وتواريخ المراحل، والملاحظة.

---

## 1) الأدوات (كلها مجانية)

| الجزء | الأداة | التكلفة |
|---|---|---|
| الواجهة | HTML + CSS + JavaScript (ملفات جاهزة في فولدر `public`) | — |
| الداتابيس وتسجيل الدخول | **Supabase** | مجاني |
| الاستضافة | **Cloudflare Pages** | مجاني، ومسموح بيه للاستخدام التجاري |
| الدومين | دومين فرعي من دومينك زي `track.yourstore.com`، أو لينك مجاني `اسم-مشروعك.pages.dev` | مجاني |
| الكود | **GitHub** | مجاني |

**مفيش سيرفر خالص.** الصفحات بتكلّم Supabase مباشرة، والحماية متطبّقة جوه الداتابيس نفسها. علشان كده الموقع مش "بينام" زي الاستضافات المجانية التانية، وبيفتح بسرعة على طول.

## 2) تجهيز Supabase (مرة واحدة)

### أ) اعمل المشروع
1. ادخل على https://supabase.com واعمل حساب، وبعدين **New project**.
2. اختار **Region** قريب منك، زي **Frankfurt (eu-central-1)**.

### ب) اعمل الجداول
**SQL Editor** ← **New query** ← الصق محتوى ملف `supabase/schema.sql` كله ← **Run**.

### ج) اعمل حساب الأدمن
1. **Authentication ← Users ← Add user ← Create new user**
   اكتب إيميلك وباسورد قوي، وفعّل **Auto Confirm User**.
2. ارجع لـ **SQL Editor** وشغّل السطر ده، بعد ما تكتب إيميلك مكان `you@example.com`:
   ```sql
   insert into public.admins (user_id) select id from auth.users where email = 'you@example.com';
   ```
3. **اقفل التسجيل الجديد** عشان محدش يعمل حساب لنفسه:
   **Authentication ← Sign In / Providers** ← اقفل **Allow new users to sign up**.
   حتى لو نسيت تقفله، اللي هيعمل حساب جديد مش هيقدر يشوف أي طلب، لأنه مش في جدول `admins`.

### د) هات بيانات الاتصال
**Project Settings ← API Keys** (أو **Data API**). هتحتاج حاجتين:
- **Project URL**: شبه `https://abcdefgh.supabase.co`
- **المفتاح العام**: يا إما **Publishable key** (بيبدأ بـ `sb_publishable_`)، يا إما **anon public** من تبويب Legacy API Keys.

حطهم في ملف **`public/config.js`**:
```js
SUPABASE_URL: 'https://abcdefgh.supabase.co',
SUPABASE_KEY: 'sb_publishable_xxxxxxxx',
STORE_NAME: 'اسم متجرك',
STORE_URL: 'https://لينك-متجرك.com',
```

> ⚠️ المفتاح العام ده معمول عشان يتحط في الموقع، فعادي يبقى ظاهر. **أوعى تحط مفتاح `service_role` أو `secret`** في الموقع أبداً.

## 3) رفعه على الإنترنت ببلاش (Cloudflare Pages)

1. ارفع الكود على **GitHub** (الفولدر ده موجود بالفعل في الريبو بتاعك)، بعد ما تعدّل `public/config.js`.
2. ادخل على https://dash.cloudflare.com واعمل حساب مجاني.
3. **Workers & Pages ← Create ← Pages ← Connect to Git**، واختار الريبو.
   لو الصفحة فتحتلك على Workers، دوّر على لينك **Pages** في نفس الصفحة.
4. في إعدادات البناء:
   | الخانة | القيمة |
   |---|---|
   | Production branch | الفرع اللي فيه الكود |
   | Framework preset | **None** |
   | Build command | سيبها **فاضية** |
   | Build output directory | `order-tracking/public` |
5. **Save and Deploy**. بعد دقيقة هيبقى عندك لينك شغال، زي `https://اسم-مشروعك.pages.dev`.

من هنا ورايح، أي تعديل ترفعه على GitHub بيتنشر على الموقع لوحده.

> **أسهل بديل:** **Netlify Drop** على https://app.netlify.com/drop. اسحب فولدر `public` وارميه في الصفحة، والموقع يبقى أونلاين علطول. ده مجاني برضه، وبيدعم ربط الدومين.

---

## 4) ربط الدومين

### لو عندك دومين (مثلاً الدومين اللي عليه متجرك)
الأحسن تعمل **دومين فرعي** زي `track.yourstore.com`، كده متجر EasyOrders يفضل زي ما هو. وده مجاني.

1. في Cloudflare Pages: مشروعك ← **Custom domains ← Set up a custom domain** ← اكتب `track.yourstore.com`.
2. Cloudflare هيقولك تضيف سجل **CNAME**. ادخل لوحة الـ DNS في المكان اللي اشتريت منه الدومين (Namecheap / GoDaddy / ...) وضيف:
   | Type | Name/Host | Value |
   |---|---|---|
   | CNAME | `track` | `اسم-مشروعك.pages.dev` |
3. استنى من دقايق لكام ساعة. شهادة HTTPS بتتعمل لوحدها ببلاش.

> متلمسش السجلات اللي EasyOrders طالبها لمتجرك. انت بس بتضيف سجل جديد اسمه `track`.

### لو معندكش دومين
- استخدم اللينك المجاني `https://اسم-مشروعك.pages.dev`، وده شغال عادي وعليه HTTPS.
- **الدومين نفسه مش بيبقى ببلاش.** دومين `.com` بيتكلف حوالي 10 دولار في السنة، والمواقع اللي كانت بتدّي دومينات مجانية مبقتش موثوقة.

## 5) ربطه بمتجر EasyOrders

- **زرار في المتجر:** ضيف في القائمة أو الفوتر لينك "تتبع طلبك" يودّي على موقع التتبع.
- **رسالة التأكيد:** ضيف في رسالة الواتساب أو الـ SMS:
  `تقدر تتابع طلبك من هنا: https://track.yourstore.com/track/رقم_الطلب`
- **الشغل اليومي:**
  1. يجيلك طلب على EasyOrders برقم، مثلاً `10234`.
  2. تفتح `/admin` وتضيف الطلب بنفس الرقم.
  3. كل ما الطلب يتنقل لمرحلة، غيّرها من القائمة.
  4. زرار **واتساب** بيفتح رسالة جاهزة للعميل.

> **ملحوظة:** إضافة الطلبات أوتوماتيك من EasyOrders (Webhook) اتشالت لما شلنا السيرفر. لو حابب ترجّعها، ممكن تتعمل بعدين كـ **Supabase Edge Function**، وده مجاني برضه.

## 6) تعديل المراحل والداتا من Supabase

من **Table Editor**:
- **`stages`**: المراحل. تقدر تغيّر الاسم (`label`) والوصف (`description`) والترتيب (`position`) والأيقونة (`icon`)، والتغيير بيظهر في الموقع علطول.
  الأيقونات المتاحة: `clipboard`, `box`, `gear`, `shield`, `package`, `truck`, `home`, `check`.
- **`orders`**: الطلبات. لو غيّرت `stage` بإيدك، اكتب الاسم الإنجليزي (`key`):

  | `stage` | اللي بيظهر للعميل |
  |---|---|
  | `received` | تم استلام الطلب |
  | `preparing` | جاري التجهيز |
  | `manufacturing` | جاري التصنيع |
  | `quality` | فحص الجودة |
  | `completed` | تم الانتهاء |
  | `shipping` | جاري الشحن |
  | `delivered` | تم التوصيل |

- **`stage_history`**: تاريخ المراحل. بيتملي **لوحده**، فماتعدّلش فيه.

## 7) تجربته على جهازك

1. نزّل **Node.js** (نسخة 20 أو أحدث) من https://nodejs.org
2. جوه فولدر `order-tracking` شغّل:
   ```bash
   npm start
   ```
3. افتح http://localhost:3000 و http://localhost:3000/admin

الموقع هيتصل بـ Supabase الحقيقي بتاعك، حسب القيم اللي في `public/config.js`.

**الاختبارات** (`npm install` وبعدين `npm test`) بتجرب قواعد الحماية على داتابيس Postgres **للتجربة بس**، لأنها بتمسح الجداول.
حط رابطها في `TEST_DATABASE_URL`، و**أوعى تحط رابط Supabase الحقيقي**.

---

## 8) الأمان

- العميل (الزائر) **مايقدرش يقرا جدول الطلبات**. بيقدر بس يسأل عن رقم طلب واحد (دالة `track_order`)، وبيرجعله حالة الطلب من غير الاسم أو الموبايل.
- **الأدمن بس** (اللي في جدول `admins`) يقدر يشوف الطلبات أو يضيف أو يعدّل أو يحذف. ده متطبّق بقواعد **Row Level Security** جوه Supabase.
- لو أرقام الطلبات متسلسلة (10234، 10235...)، أي حد ممكن يجرب أرقام ويشوف مرحلة طلبات تانية. ده سبب إن الصفحة مش بتعرض أي بيانات شخصية.
- **الخطة المجانية في Supabase:** المشروع ممكن **يتوقف مؤقتاً** لو مفيش أي نشاط عليه حوالي أسبوع. بترجّعه بضغطة **Restore**، والبيانات مش بتضيع.
- **نسخة احتياطية:** من **Table Editor ← Export to CSV**.
