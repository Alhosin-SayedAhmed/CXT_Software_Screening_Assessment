# موقع تتبع الطلبات (مراحل التصنيع)

موقع صغير منفصل عن متجرك على **EasyOrders**:

- **صفحة العميل** (`/`): العميل بيكتب رقم الطلب ويشوف طلبه وصل لأنهي مرحلة، زي: تم الاستلام ← جاري التجهيز ← جاري التصنيع ← فحص الجودة ← تم الانتهاء ← جاري الشحن ← تم التوصيل.
- **لينك مباشر لكل طلب** (`/track/10234`): تبعته للعميل على واتساب ويفتح على طلبه علطول.
- **لوحة التحكم** (`/admin`): بتدخلها بباسورد. فيها بتضيف رقم الطلب اللي جالك من EasyOrders، وتغيّر المرحلة من قائمة، وتنسخ لينك التتبع أو تبعته للعميل على واتساب بضغطة.

- **الداتا كلها على Supabase**: أي طلب بتضيفه بيتخزن هناك، والموقع بيقرا منه علطول. ولو عدّلت حاجة من لوحة Supabase نفسها، صفحة العميل بتتحدّث لوحدها خلال 20 ثانية، ولوحة التحكم خلال 30 ثانية.

> من باب الخصوصية، العميل مش بيشوف اسم ولا رقم موبايل. اللي بيظهر له بس: رقم الطلب، والمنتج، والمرحلة، وتواريخ كل مرحلة، والملاحظة لو كتبت واحدة.

---

## 1) الأدوات المستخدمة (وليه)

| الجزء | الأداة | دورها |
|---|---|---|
| Frontend (الواجهة) | HTML + CSS + JavaScript عادي | صفحة العميل ولوحة التحكم. من غير React ولا build، يعني سهل تعدّل فيه |
| Backend (السيرفر) | **Node.js** + **Express** | الـ API اللي بيحفظ ويرجّع الطلبات ويتحقق من باسورد الأدمن |
| قاعدة البيانات | **Supabase** (PostgreSQL) | كل الطلبات وتاريخ كل مرحلة متخزنين أونلاين، وتقدر تشوفهم وتعدّلهم من لوحة Supabase |
| الاستضافة | **Railway** (أو أي VPS عليه Docker) | السيرفر بيشتغل عليها 24 ساعة |
| الدومين | من أي مكان بتشتري منه (Namecheap / GoDaddy / ...) | بتعمل دومين فرعي زي `track.yourstore.com` |
| الكود | **GitHub** | بتحفظ عليه الكود، وRailway بيسحب منه أوتوماتيك |

## 2) تجهيز Supabase (مرة واحدة)

1. ادخل على https://supabase.com واعمل حساب، وبعدين **New project**.
2. اكتب اسم المشروع واختار **Database Password**.
   خلي الباسورد **حروف إنجليزي وأرقام بس** (من غير رموز زي `@` و`#` و`/`)، عشان مايبوّظش الرابط. واحفظه عندك.
3. في **Region** اختار أقرب مكان ليك، زي **Frankfurt (eu-central-1)**.
4. بعد ما المشروع يجهز، دوس زرار **Connect** اللي فوق ← **Connection string** ← اختار **Session pooler**.
   انسخ الرابط، هيبقى شبه كده:
   ```
   postgresql://postgres.abcdefgh:[YOUR-PASSWORD]@aws-0-eu-central-1.pooler.supabase.com:5432/postgres
   ```
   حط باسورد الداتابيس مكان `[YOUR-PASSWORD]`، والقوسين `[ ]` يتشالوا.
   ده الـ `DATABASE_URL`.

> استخدم **Session pooler** مش **Direct connection**، لأن الـ Direct بيشتغل على IPv6 بس، وأغلب الاستضافات (زي Railway) ممكن ماتعرفش توصله.

**الجداول بتتعمل لوحدها** أول ما السيرفر يشتغل. ولو حابب تعملها بإيدك: **SQL Editor** ← الصق محتوى `supabase/schema.sql` ← **Run**.

### تشوف وتعدّل الداتا من Supabase

من **Table Editor** هتلاقي جدولين:
- `orders`: الطلبات. تقدر تعدّل أي خانة منه، والموقع هيعرض التعديل.
- `stage_history`: تاريخ كل مرحلة دخلها الطلب. بيتملي **أوتوماتيك**، حتى لو غيّرت المرحلة بإيدك من Supabase، فماتعدّلش فيه.

لو هتغيّر المرحلة من Supabase، لازم تكتب الاسم الإنجليزي (الـ `key`) بالظبط، مش الاسم العربي:

| اكتب في `stage` | اللي بيظهر للعميل |
|---|---|
| `received` | تم استلام الطلب |
| `preparing` | جاري التجهيز |
| `manufacturing` | جاري التصنيع |
| `quality` | فحص الجودة |
| `completed` | تم الانتهاء |
| `shipping` | جاري الشحن |
| `delivered` | تم التوصيل |

> **الأمان:** الجداول عليها حماية **Row Level Security**. يعني المفاتيح العامة بتاعة Supabase (`anon`) ماتقدرش تقرا أو تعدّل أي طلب. الموقع بس هو اللي بيوصل للداتا، عن طريق `DATABASE_URL`، فخلي الرابط ده سر.

> **الخطة المجانية:** Supabase ممكن **يوقّف مؤقتاً** المشروع المجاني لو مفيش أي نشاط عليه حوالي أسبوع. ساعتها بترجّعه بضغطة **Restore** من لوحة Supabase، وبياناتك مش بتضيع. لو الموقع شغال وعليه زيارات، المشكلة دي مش هتحصل.

## 3) تشغيله على جهازك للتجربة

1. نزّل **Node.js** (نسخة 20 أو أحدث) من https://nodejs.org
2. افتح الـ Terminal جوه فولدر `order-tracking` وشغّل:
   ```bash
   npm install
   cp .env.example .env     # على ويندوز: copy .env.example .env
   ```
3. افتح ملف `.env` واكتب:
   - `ADMIN_PASSWORD`: باسورد لوحة التحكم (8 حروف على الأقل)
   - `DATABASE_URL`: رابط Supabase من الخطوة اللي فاتت
4. شغّل:
   ```bash
   npm start
   ```
5. افتح:
   - صفحة العميل: http://localhost:3000
   - لوحة التحكم: http://localhost:3000/admin

**الاختبارات** (`npm test`) محتاجة داتابيس Postgres **للتجربة بس**، لأنها بتمسح الجداول.
حط رابطها في `TEST_DATABASE_URL`، و**أوعى تحط رابط Supabase الحقيقي بتاعك**.

## 4) تغيير المراحل

المراحل موجودة في ملف `src/stages.js`. تقدر تغيّر الأسماء والوصف، أو تزوّد وتشيل مراحل.
متغيّرش الـ `key` بتاع مرحلة لو عندك طلبات واقفة عليها.

## 5) رفع الموقع على الإنترنت (Railway)

1. **ارفع الكود على GitHub** (الفولدر ده موجود بالفعل في الريبو بتاعك).
2. ادخل على https://railway.com واعمل حساب بـ GitHub.
3. **New Project ← Deploy from GitHub repo** واختار الريبو.
4. من **Settings** بتاعة الخدمة:
   - **Root Directory** = `order-tracking`
   - Railway هيلاقي الـ `Dockerfile` ويبني بيه أوتوماتيك.
5. من **Variables** ضيف:
   ```
   DATABASE_URL=رابط Supabase (Session pooler)
   ADMIN_PASSWORD=باسورد قوي
   SESSION_SECRET=كلام عشوائي طويل
   STORE_NAME=اسم متجرك
   STORE_URL=https://لينك-متجرك.com
   NODE_ENV=production
   ```
   عشان تعمل `SESSION_SECRET`، شغّل الأمر ده على جهازك وانسخ الناتج:
   `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`
6. من **Settings ← Networking** اضغط **Generate Domain** عشان تاخد لينك مؤقت تجرب عليه.

> **التكلفة:** Railway بيدّيك فترة تجربة، وبعدها الخطة الأساسية حوالي 5 دولار في الشهر. Supabase الخطة المجانية بتاعته كفاية جداً للموقع ده.
> بما إن الداتا بقت على Supabase، تقدر كمان تستضيف السيرفر على **Render** مجاناً. بس السيرفر المجاني هناك بينام لو مفيش زيارات، فأول زيارة بعدها بتاخد حوالي 30 إلى 50 ثانية.
> **بديل:** أي VPS (زي Hostinger أو DigitalOcean أو Contabo) تثبّت عليه Docker وتشغّل:
> `docker build -t tracker . && docker run -d -p 3000:3000 --env-file .env --restart always tracker`
> وتحط قدامه Caddy أو Nginx عشان شهادة HTTPS.

## 6) ربط دومين (مثلاً `track.yourstore.com`)

الأحسن تستخدم **دومين فرعي** من نفس دومين متجرك. كده متجر EasyOrders يفضل زي ما هو، والتتبع يبقى على `track.`.

1. في Railway: **Settings ← Networking ← Custom Domain** ← اكتب `track.yourstore.com`.
   Railway هيدّيك قيمة **CNAME** (حاجة شبه `xxxx.up.railway.app`).
2. ادخل على لوحة الـ DNS في المكان اللي اشتريت منه الدومين، وضيف سجل:
   | Type | Name/Host | Value |
   |---|---|---|
   | CNAME | `track` | القيمة اللي Railway اداهالك |
3. استنى من دقايق لكام ساعة. شهادة الـ HTTPS بتتعمل أوتوماتيك.

> متلمسش سجلات الـ DNS اللي EasyOrders طالبها لمتجرك. انت بس بتضيف سجل جديد اسمه `track`.

## 7) ربطه بمتجر EasyOrders

- **زرار في المتجر:** من لوحة EasyOrders ضيف في القائمة (Menu) أو الفوتر لينك اسمه "تتبع طلبك" يودّي على `https://track.yourstore.com`.
- **رسالة التأكيد:** لو بتبعت رسالة واتساب/SMS بعد الطلب، ضيف فيها:
  `تقدر تتابع طلبك من هنا: https://track.yourstore.com/track/رقم_الطلب`
- **طريقة الشغل اليومية:**
  1. يجيلك طلب على EasyOrders برقم مثلاً `10234`.
  2. تفتح `/admin` وتضيف الطلب بنفس الرقم (واسم العميل والموبايل والمنتج لو حابب).
  3. كل ما الطلب يتنقل لمرحلة، غيّرها من القائمة. العميل هيشوف التحديث فوراً.
  4. زرار **واتساب** بيفتح رسالة جاهزة للعميل فيها المرحلة واللينك.

### (اختياري/تجريبي) إضافة الطلبات أوتوماتيك من EasyOrders

EasyOrders عندها **Webhooks** في لوحة البائع (قسم Public API). معنى كده إنها تقدر تبعت كل طلب جديد للموقع ده لوحده من غير ما تكتبه بإيدك.

1. ضيف متغير `WEBHOOK_SECRET=كلمة-سرية-طويلة` في Railway.
2. في EasyOrders، حط رابط الـ Webhook:
   `https://track.yourstore.com/api/webhook/easyorders?key=كلمة-سرية-طويلة`
3. اعمل طلب تجريبي، وبص في **Logs** بتاعة Railway. هتلاقي سطر `[webhook] received keys: ...`.

⚠️ **مهم:** الكود بيدوّر على رقم الطلب في حقول زي `short_id` و`order_number` و`id`، لكن شكل البيانات اللي EasyOrders بتبعتها **ماتجربش على حساب حقيقي**. لو الطلب ماتضافش، أو اتضاف برقم مختلف عن اللي العميل بيشوفه، ابعت سطر الـ Logs وهنظبط الحقل الصح في `src/app.js`. لحد ما تجرب الطريقة دي، الإضافة اليدوية من `/admin` شغالة 100%.

## 8) نصايح أمان

- خلي `ADMIN_PASSWORD` قوي ومتشاركهوش مع حد.
- ملف `.env` مش بيترفع على GitHub (موجود في `.gitignore`).
- لو أرقام الطلبات عندك متسلسلة (10234، 10235...)، أي حد ممكن يجرب أرقام ويشوف مرحلة طلبات تانية. ده سبب إن الصفحة مش بتعرض أي بيانات شخصية.
- خلي `DATABASE_URL` سر، لأن اللي معاه الرابط ده يقدر يعدّل كل الداتا.
- **نسخة احتياطية:** Supabase بيعمل نسخ احتياطية يومية في الخطط المدفوعة. على الخطة المجانية، تقدر تنزّل الداتا من **Table Editor ← Export to CSV**.
